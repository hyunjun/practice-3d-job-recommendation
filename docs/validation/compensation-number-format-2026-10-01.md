# 보상 금액의 숫자 표기 검증

상태: 최종 소스의 검사와 검증 근거에 대한 전원 승인을 완료했습니다. Git 보존·임시 파일 정리는 후속 기록으로 확인합니다.

`EUR 88 000–124 000`처럼 공백으로 천 단위를 나눈 급여를 전체 범위로 읽도록 보완했습니다. `EUR 62.000–118.000`처럼 점의 역할이 모호한 값이나 잘못된 숫자 표기는 원문 근거로 남깁니다. 지원하는 연결 기호·주석으로 이어진 범위에서는 잘못된 한쪽을 버리고 다른 쪽만 확정 금액으로 표시하지 않습니다.

보상 해석 버전 3은 이전 본문·보관 근거를 다시 읽으며 저장한 메모·지원 상태·조회 시각을 유지합니다. 게시판이 별도 숫자 필드로 제공한 급여는 보존합니다. 근거를 복구할 수 없는 이전 저장 금액은 기존의 “이전 기록” 표시를 유지합니다. [설계 계약](../design/compensation-number-format.md)에 문법과 한계가 있습니다.

## 실제 자료 대조

새 수집 없이 보관된 공고 6,819개를 대조했습니다. 의미 있는 보상 변경 70건을 각각 분류했고, 비교 가능한 급여는 1,215개에서 1,224개로 늘었습니다. 새로 비교 가능한 9건은 공백 표기 3건과 도시·급여 항목 뒤 구분 기호를 복원한 6건입니다. 비교 가능했던 공고가 제외된 경우는 없습니다.

구조화된 급여 2,436건은 해석 버전을 제외한 전체 공고 필드의 해시가 전후 동일합니다. 급여 외 필드의 변경도 없습니다. 별도로 보관한 Himalayas 응답 12개·원 행 189개를 대조했으며, 보상 변경 2건은 위 전체 자료에서 검토한 것과 같습니다. 선택된 급여 출처와 대조에 기록한 공고 식별 정보·시각·출처 정보는 유지됐습니다.

원문의 숫자 표기 조사에는 급여가 아닌 문장도 포함됩니다. 표기 빈도를 급여 수나 결함 수로 해석하지 않습니다. 이 대조는 과거 수집본의 재해석 결과이며 현재 공고가 열려 있다는 확인이 아닙니다.

## 독립 검증과 발견한 문제

주 담당은 제품·통합·문서와 실제 자료 대조를, GPT-6 Astra/max는 독립 설계·코드·근거 검토를, Claude Code Fable 5.1/max는 테스트 작성·실행을 맡습니다. 설계·구현·검증 승인은 각 단계의 같은 내용 해시에 연결합니다. Claude 응답에서 모델을 확인했으며, 백엔드의 실제 effort 값은 별도로 노출되지 않습니다.

검토 과정에서 범위 연결 기호와 부호의 소유 관계, 주석 뒤 숫자 조각, CR 줄바꿈, 마지막 통화의 소속, 도시 항목의 구분 기호, 숫자 나눗셈 꼬리와 반복 탐색 비용을 보완했습니다. 각 문제는 독립적으로 작성한 명시적 기대값의 회귀 검사에 반영했습니다.

첫 구현 검토에서는 검색을 바꾼 직후 이전 결과를 누를 수 있는 테스트 순서 문제가 발견됐습니다. Fable이 요청한 제목의 결과를 기다려 누르도록 수정했고, 금액·필터·저장 정보 등의 기대값은 유지했습니다.

첫 실행의 타입 검사·단위 검사 2,978개와 빌드는 통과했으나, 개발 모드 E2E는 **193개 통과·1개 실패**였습니다. 실패한 검사는 원문에 `EUR 54.000–91.000`이 있어야 한다고 확인한 뒤 같은 전체 영역에 `EUR 54`가 없어야 한다고 검사했습니다. 표시된 숫자 행은 올바른 USD 한 구간이었고, 원문 보존 요구와 테스트 조건이 충돌했습니다. 세 담당자 모두 사전 검토에서 놓친 문제였습니다.

Fable이 제외 조건의 대상을 실제 숫자 행으로 한정했습니다. 정확한 USD 한 구간, 포르투갈 원문, 일부 확인 안내와 뒤이은 필터·통계 기대값은 유지했습니다. 실패한 실행에서 해당 지점 뒤의 검사는 실행되지 않았으며 운영 빌드 E2E도 시작하지 않았습니다. 이 실패와 수정 전 소스·검토 기록을 보존합니다.

## 최종 실행 범위

최종 소스·테스트 419파일의 내용 해시는 `fd14f53434ae18b1721f7194a5ac6e1647a5d5e653999a56dea8d83239438359`입니다.

| 타입·단위 검사 | 89파일·2,978개 통과, 실패·미실행·todo 0 |
| 클라이언트·서버 빌드 | 통과 |

E2E는 작업자 1개·재시도 0회로 실행했습니다. 보고서의 검사 식별자를 전부 대조해 두 모드의 검사 목록이 같음을 확인했습니다. 모든 실행에서 소스·설계·실행 설정이 유지됐으며, 운영 E2E는 같은 소스로 통과한 빌드 산출물을 사용했습니다. 앞서 실패했던 사례의 뒤쪽 숫자 목록·연봉 필터·도시 중앙값 검사도 두 모드에서 완료됐습니다.

새 검사는 숫자 문법과 경계, 이전 보상·캐시 객체의 재해석, 제공자별 우선순위, 저장·재방문·CSV, 검색·연봉 필터·도시 중앙값, 320px 배치·접근성을 포함합니다. 캐시 객체를 다루는 새 단위 검사를 실제 디스크 재시작 E2E로 보고하지 않습니다. 선택한 20개 파일은 관련 회귀 범위이며 저장소의 모든 E2E를 뜻하지 않습니다.

두 모드에서 생성한 데스크톱 1440px·모바일 320px 화면 총 6개를 주 담당이 직접 검토했습니다. 급여 숫자와 원문 근거, 줄바꿈·고정 버튼 배치에 문제가 관찰되지 않았습니다. 모바일의 가로 넘침·Axe 검사는 해당 두 보상 상태에서 통과한 결과이며 전체 앱의 접근성을 보증하지 않습니다.

검증용 서버·브라우저의 소유 프로세스 잔여는 0입니다. 실행 전후 같은 작업 전용 잠자기 방지와 AC 전원을 확인했고, 두 E2E 실행 중 Sleep·Wake·DarkWake 기록은 없었습니다. 영구 전원 설정은 바꾸지 않았습니다.

[실행·합의 기록](compensation-number-format-2026-10-01.json)에 각 판단과 해시를 보존합니다. Git 보존·정리 결과는 완료 후 별도로 연결합니다.

## 남은 한계

명시된 숫자 문법·연결 기호·주석을 지원합니다. 단어로 된 기간 연결이나 중간 지역 설명 등 지원 범위 밖 문장은 기존 해석을 유지하며, 모든 미지원 문장의 금액을 일괄 거부한다는 의미가 아닙니다. 지역·금액 크기로 통화·지급 기간을 추측하거나 원문의 잘못된 자릿수를 보정하지 않습니다. 기본급과 보너스의 분류, 급여 검토 주기와 지급 기간의 구분은 별도 개선 후보입니다.

임시 화면·trace·로그·빌드·브라우저·자료 사본은 최종 검증과 합의 후 재사용 도구·결론·실패 기록을 로컬 Git에 보존하고 정리합니다. 다시 얻을 수 없는 원본과 관측 이력은 이유·위치를 기록해 무시되는 로컬 자료로 남깁니다.
