# 게시 근거 파일 검증 — 2026-10-26

수집 CLI가 게시할 카탈로그의 메타데이터와 정확한 전송 바이트의 크기·SHA-256을 파일로 남기도록 했다. 게시 요청이 나중에 실패해도 완성된 근거 파일은 보존한다. 원문 공고 본문은 포함하지 않는다.

로컬 검증은 주 구현 담당과 Astra가 같은 소스·실행 결과에 명시적으로 동의했다. 실제 공급자 수집, GitHub artifact 업로드, 132개 소스 게시, 운영 화면과 정기 실행은 이 검증에서 수행하지 않았다. 새 변경의 배포 완료를 뜻하지 않는다.

## 변경

- `ORBIT_PUBLICATION_EVIDENCE_FILE`을 지정한 collect 실행은 원문 임시 디렉터리 밖의 절대 경로에 파일을 배타적으로 생성한다. 쓰기가 끝나야 버전·바이트 수·해시를 결과에 기록한다.
- 파일 충돌이나 부분 쓰기는 게시 요청 전에 실패한다. 쓰기가 끝난 뒤 begin/chunk/commit/metrics 단계에서 실패하면 완성된 근거를 남긴다. 환경변수를 사용하지 않는 실행과 rollback의 기존 동작은 유지한다.
- 준비 스크립트가 현재 실행의 결과와 근거 파일을 엄격하게 대조한다. 완료 영수증이 없는 실패를 오래된 파일로 보완하지 않는다.
- GitHub workflow는 현재 실행 전용 결과 파일을 사용하고, 수집·출력 실패를 보존한다. 준비 조건을 만족한 파일만 고정 버전의 upload-artifact로 7일간 보관한다.

동작과 운영 설정은 [Cloudflare 문서](../cloudflare.md)에, 소스·검토·실행의 전체 해시는 [검증 근거](publication-evidence-2026-10-26.json)에 기록했다.

## 실제 검사

독립 테스트 담당이 보존된 Node 26.12.1과 의존성으로 한 번 실행했다. 소스 manifest03의 627개 파일을 기준으로 9개 단계가 모두 통과했다. 타입 검사, 테스트 수집·실행·결과 대조, 실행 전후 의존성 검사를 포함한다.

| 검사 | 결과 |
| --- | --- |
| 루트 TypeScript `tsc --noEmit` | 통과 |
| publication evidence / prepare / workflow 단위 검사 | 12 / 58 / 10개 통과 |
| 기존 publication build / client / collector 단위 검사 | 22 / 15 / 25개 통과 |
| 합성 공급자·로컬 게시 서버를 사용하는 실제 CLI 검사 | 기존 15개와 신규 9개, 총 24개 통과 |

단위 검사는 총 142개다. 실제 수집 목록, JSON, JUnit의 테스트 식별자와 중복 개수를 대조했다. 실패·미실행·건너뜀·재시도·보고된 전역 오류는 0개다. 실행은 병렬 파일 검사와 캐시를 끄고 worker 1개, retry 0, bail 1로 제한했다. 단위 검사 600초, CLI 900초의 제한을 유지했으며 전체 외부 실행은 약 156초 후 종료 코드 0으로 끝났다.

CLI 검사는 정상 게시 및 begin/chunk/commit/metrics 실패의 실제 출력·근거 파일을 준비 스크립트에 연결해 정확한 바이트·해시와 ready 상태를 확인했다. 실제 7바이트 부분 쓰기에서는 완료 영수증과 게시 변이가 없고 ready가 false인지 검사했다. 충돌·취소·rollback과 프로세스 소유권의 기존 기대값도 유지했다.

이전 Daangn 구현의 전체 빌드·Worker·브라우저 검증은 [앞선 검증 기록](reference-official-jobs-2026-10-26.md)에 별도로 보존했다. 이번 결과를 전체 앱 검사 재실행으로 계산하지 않는다.

## 첫 실행의 실패와 수정

첫 실행은 단위 검사 134개 통과 후 workflow 임시 경로 검사 1개가 실패했다. 나머지 단위 검사 7개와 CLI 24개는 실행되지 않았다. macOS의 인자 없는 `mktemp -d`가 테스트에서 지정한 `TMPDIR`보다 Darwin 사용자 임시 경로를 우선하는 가정 차이였다.

합성 `mktemp`의 해당 분기만 테스트 소유 디렉터리의 명시적인 `raw.XXXXXX` 템플릿을 사용하도록 수정하고 경로 진단을 추가했다. 제품 workflow, 경로 포함·삭제 기대값, 검사 수와 제한 시간은 바꾸지 않았다. 두 번째 실행에서 142개와 24개 전체를 새로 실행했다. 첫 실패 당시에는 정확한 원문 임시 경로와 이후 삭제 검사가 기록되지 않았으므로, 그 삭제를 소급하여 증명하지 않는다.

## 종료·보존·한계

소스는 실행 중 20회 확인에서 동일했고, 제어 파일 43개와 의존성 13,611개 기록·1,088개 디렉터리의 보존 검사가 통과했다. 소유 프로세스의 최종 범위 검사에서 잔여 일치는 없었고 잠자기 방지 프로세스와 잠금은 해제됐다.

CLI의 esbuild 서비스 25개는 종료 callback이 기록되지 않았다. 부모 종료와 해당 PID를 포함한 최종 범위의 부재를 확인했지만 개별 종료 코드·신호는 알 수 없다. Vitest worker의 실제 SIGTERM 14건과 guard의 종료 코드 -15를 정상 코드 0으로 바꾸어 기록하지 않았다. 전원 기록의 약 153초 검사 구간에 Sleep/Wake/DarkWake 사건은 없었다. 이는 호스트 전체 프로세스·네트워크의 부재나 연속적인 전원 상태 증명이 아니다.

테스트별 CLI 전송·근거·ready 파일은 기대값 검사 후 해당 테스트가 정리했다. 별도 원문 transcript로 보존되어 있다고 주장하지 않는다. 실행 직후 보존 목록은 753개 항목(파일 731개, 디렉터리 22개, 파일 합계 22,981,569바이트)이며 이후 보고서는 별도 해시로 연결했다.

상세 로그와 과거 실패 근거는 원래 checkout의 무시되는 `.local/research/reference-official-jobs-2026-10-25/`에 있다. 진행 중인 실제 수집·게시 검증에서 참조하므로 아직 정리하지 않았다. 공개 문서에는 검증 결론과 해시를 남기며 실제 공고 원문을 넣지 않는다. 전체 단계의 임시 자료 정리와 새 공고의 운영 반영은 아직 완료되지 않았다.
