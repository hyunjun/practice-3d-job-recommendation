# Worker 공고 본문 전달 개선 검증

79단계 · 2026-10-01 UTC 시작, 2026-10-02 UTC 최종 검사와 전원 합의 완료. 타입·단위 검사, 빌드, 개발·배포 E2E가 통과했습니다. 주 담당·GPT-6 Astra·Claude Code Fable 5.1 모두 같은 최종 소스와 근거를 명시적으로 승인했습니다. 이 문서의 최초 커밋 시점에는 Git 원본 보존·임시 파일 정리가 남아 있으며, 실제 정리 결과를 별도로 기록합니다.

## 변경

시간이 지나 `이전 조회 공고`로 바뀔 때 긴 공고 본문을 반복 전달하던 경로를 개선했습니다. Worker는 본문이 같으면 오래됨 상태의 변경분만 보내고, 새 공고·본문 변경·만료 후 복원에는 전체 본문을 보냅니다. 수신 측은 이전 화면과 저장된 공고 객체를 직접 바꾸지 않습니다.

Worker 요청·응답의 버전과 변경분의 ID 관계를 검사합니다. 잘못된 응답은 연결 실패로 처리하며, 마지막 정상 결과와 검색·저장 상태를 유지하고 명시적 재조회로 복구합니다. 기존 freshness·수집·검색·점수·저장 정책은 유지합니다. 세부 계약은 [설계 문서](../design/catalog-worker-aging.md)에 있습니다.

## 검증

주 담당은 제품 구현·통합·문서, GPT-6 Astra는 독립 설계·소스·근거 검토, Claude Code Fable 5.1은 테스트 작성과 실행을 맡았습니다. 설계·수정 전 실패 재현·구현 검토·최종 검증 단계마다 같은 소스·설계·근거에 세 담당자가 명시적으로 동의한 기록을 남겼습니다. Astra의 reasoning과 Fable의 effort는 `max`로 요청했으며, 노출되지 않은 백엔드 설정을 측정한 값으로 표현하지 않습니다.

## 확인한 효과와 한계

600개의 가상 공고와 총 1,200만 description 문자를 사용하는 단위 검사에서, 모든 순방향 시간 경계를 지날 때 본문은 최초 한 번씩만 전달합니다. 만료 후 복원은 별도 구간으로 본문을 다시 보내고, 이후 fresh 전환은 상태 변경만 보냅니다. 실제 브라우저 Worker 검사에는 총 18만 description 문자를 가진 가상 공고 9개를 사용합니다.

본문 개수와 문자 수는 논리적 전달 구조의 검증값입니다. 실제 structured clone 바이트, HTTP 대역폭, CPU·메모리·응답 시간의 측정값은 아닙니다. 검색 인덱스·점수·facts 재계산과 deadlines 전달 비용은 남아 있으며, 전체 재파싱이나 일부 legacy 마이그레이션에서는 본문이 다시 전달될 수 있습니다.

PNG는 촬영 순간의 표시와 가독성, Worker JSON은 해당 계층의 메시지를 뒷받침합니다. 화면 복귀 JSON의 요청 11개와 응답 11개를 “요청 없음”으로 표현하지 않습니다. 추가 catalog API 요청이 없다는 결과는 별도의 API 경로 assertion에 근거합니다. 가상 시각을 물리적 실행 시간으로 표현하지 않습니다.

## 실패 이력과 보존

수정 전 회귀 실패, 이전 후보의 캡처 위치·모바일 필터 Apply 실패, 전원 근거가 오래돼 중단된 개발 실행을 원래 결과로 보존했습니다. 캡처는 카드 단위 스크롤로 보완하면서 완전한 화면 노출과 겹침 금지 조건을 유지했습니다. 모바일 필터 검사는 수집·미리보기 준비, 실제 dialog 닫힘과 저장 상태를 확인하도록 보강하고 320px 지연 미리보기 흐름을 추가했습니다.

앞선 전체 배포 실행은 573개 assertion이 통과했지만 실행 중 Sleep 이벤트가 있어 최종 근거에서 제외했습니다. 이후 실행도 Fable 제공자의 API 거절로 중단됐고 완성된 보고서가 없으므로 통과로 취급하지 않습니다. 새 세션의 독립 검토와 세 담당자의 정확한 소스·세션 합의를 마친 뒤 별도 전체 실행을 진행했고, 최종 실행은 573개가 모두 통과했습니다. 실행 전후 같은 소유 프로세스의 전원 근거를 확인했으며 기록된 실행 구간에 Sleep·Wake·DarkWake 이벤트는 없었습니다.

최종 실행 요약의 대기 호출 횟수에도 오기가 있었습니다. 원본 요약은 46회지만 실제 도구 기록은 52회(진행 중 51회·종료 확인 1회)입니다. 원본을 보존하고 최종 검토에서 작성자의 명시적 정정을 확인했습니다. 진행 중 상태의 종료 코드는 양수 `75`, 종료 확인은 `0`입니다. 전체 일반 로그의 브라우저 진단과 테스트용 하위 프로세스의 종료 상태도 통과 결과와 구분해 남겼습니다.

주 담당이 화면 검토 중 종료 상태를 늦게 확인해 이전 실행이 계속되고 있다고 안내했던 부분도 정정해 기록했습니다. 해당 실행에서 읽은 화면은 최종 배포 근거로 사용하지 않습니다. 제공자 내부의 거절 원인이나 잠자기의 실제 원인을 추정하지 않습니다.

첫 최종 자료에서는 Astra가 과거 합의 파일의 참조 경로 오류를 발견했습니다. 당시 파일과 해시는 보존돼 있었지만 경로가 최신 파일을 가리켰습니다. 주 담당도 오류를 확인해 기존 승인을 보류하고, 원본 자료를 보존한 뒤 과거 파일의 고정 경로로 수정했습니다. 수정본의 파일 참조 233개를 대조했으며 소스·검사 결과는 그대로입니다.

Fable의 첫 읽기 전용 최종 검토는 필수 원본 92개를 읽고 해시를 확인했지만, 30분 제한으로 최종 판단 없이 종료됐습니다. 이 호출을 승인으로 취급하지 않습니다. 같은 세션에서 수정본과 원본 근거를 이어서 검토했으며, 종료 기록과 실패 이력도 보존합니다.

두 번째 읽기 전용 검토는 정상 종료됐지만, 긴 JSON 응답이 출력 제한으로 두 조각으로 나뉘어 최종 결과 필드에는 뒤쪽만 저장됐습니다. 두 공개 응답 조각을 값 변경 없이 연결하면 승인 의견과 원본 92개 관찰이 담긴 정상 JSON이 되지만, 이를 원래 결과 파일 대신 사용하지 않았습니다. 요약의 추가 이력 수는 36개에서 33개, 한계 수는 37개에서 42개, PNG의 고유 내용 수는 33종에서 28종으로 정정했습니다. 개발·배포 모드의 PNG 36쌍은 바이트가 같지만, 필수 이름 72개를 모두 유지합니다. Worker JSON 비교에서는 모드 이름과 제어된 시각 필드의 차이를 함께 구분합니다.

세 번째 검토에서 Fable이 같은 세션으로 완결된 JSON 문서를 직접 제출했고, 실제 결과 필드와 저장 파일이 일치하는 것을 확인했습니다. 세 담당자는 이 문서의 원본 92개 관찰과 정정 내용을 검토하고 동일한 최종 자료 `053370d161f603719df554fd79e4c69c701d6e7672e8040fe19c530217875bed`를 승인했습니다. 두 번째 호출의 불완전한 원본은 그대로 보존합니다. 최종 자료 생성 뒤에 발생한 이 보고서 전달·정정 이력은 [별도 기록](catalog-worker-aging-review-delivery-2026-10-02.json)에 연결하며, 확정한 자료를 다시 작성하지 않습니다.

합의가 끝난 제품·테스트·문서를 먼저 커밋합니다. 가치 있는 조사·검증·실패·합의 원본은 공개하지 않는 로컬 Git ref에 보존하고 바이트를 대조한 뒤 임시 빌드·캐시·보고서·화면·로그·스크립트와 소유 프로세스를 정리합니다. 다시 얻을 수 없는 실제 수집 원본과 관측 이력은 지정된 로컬 보관 위치에 남깁니다. 정리 결과는 실행 후 별도 커밋으로 기록합니다.

실행 근거와 한계는 [최종 검토 자료](catalog-worker-aging-final-evidence-2026-10-01.json), 실제 세 담당자의 승인과 검증 요약은 [단계 기록](catalog-worker-aging-2026-10-01.json)에 있습니다. 단계 기록은 정리 전 시점의 기록이며, 승인 자체를 임시 자료 삭제 완료나 무결점 보장으로 표현하지 않습니다.
