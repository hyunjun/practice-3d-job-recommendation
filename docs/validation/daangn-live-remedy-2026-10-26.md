# 당근 실제 수집 실패 수정과 검증

2026-10-26 KST 기준, 수정 후 로컬 검증의 12개 단계가 통과했고 실제 실행은 종료 코드 0으로 끝났다. 같은 소스·실제 검증 보고서에 대한 Main·Astra의 명시적 합의를 마쳤다. 소스·테스트와 검증 결론을 함께 Git에 보존한다. 새 수집 코드의 운영 반영, 실제 신규 공고 제공 및 후속 자동 발행은 아직 완료하지 않았다.

## 문제와 수정

첫 실제 수집은 기존 공개 catalog를 조회하고 robots 두 건과 목록 두 건을 받은 뒤 문서 파싱에서 중단됐다. HTTP 200 응답만으로 완전한 수집을 인정하지 않았으며, 새 공고를 확보하거나 발행했다고 보고하지 않는다. 실패한 실행과 당시 잘못 기록된 회사·수집 차수 표시는 원본 그대로 보존한다.

목록에는 실제 `</html>` 뒤에 본문이 비어 있는 외부 모듈 스크립트가 붙어 있었다. 기존 제품 파서와 독립 검증기는 이를 불완전한 문서로 거부했다. 수정안은 파서가 실제로 처리한 첫 HTML 종료 태그의 원문 위치를 보존하고, 뒤따르는 원문 전체를 검사한다. HTML 공백, 완전히 닫힌 주석, 본문이 비어 있고 완전히 닫힌 외부 모듈 스크립트만 허용한다. 스크립트를 실행하거나 가져오지는 않는다.

잘린 문서, 가짜 종료 태그, 설명되지 않는 후행 마크업, 중복 속성, 닫히지 않은 스크립트, 공백만 있더라도 본문이 있는 스크립트는 계속 거부한다. 응답 크기·UTF-8·노드 수·전체 목록·회사 구분·공고 ID·상세 정규 URL 검사를 유지한다.

공통 요청 대기열에서는 각 요청을 넣을 때의 비동기 실행 문맥을 유지하도록 수정했다. 회사와 수집 차수가 다른 요청 사이에서 호출자 정보가 섞이거나 누락되는 문제를 해결한다. 요청 순서, 최소 3초 간격, robots 지연, 취소·응답 읽기·정리 정책은 유지한다. 이 코드는 Node 수집기에만 포함된다.

## 수정 전후의 실제 검사

별도 테스트 담당이 원래 제품과 검증기로 실행한 두 재현은 각각 종료 코드 1이었다. 제품에서 정상 HTML 오판 네 건과 요청 문맥 불일치 한 건, 검증기에서 정상 HTML 오판 두 건이 계획한 위치에서 실패했다. 원본 `FAILED` 상태를 유지하고 결함 재현의 근거로 사용한다. 이후 도달하지 못한 긍정 기대값이나 선택하지 않은 검사를 통과로 세지 않는다.

가상 요청의 문맥 재현에서는 첫 요청만 호출자 정보를 유지하고 이후 다섯 요청에서 정보가 누락됐다. 이는 이전 실제 실행의 특정 오표시를 그대로 재현했다는 뜻이 아니다.

수정 후에는 같은 회귀 기대값을 포함해 다음 검사를 실행했다.

새 회귀 검사는 제품 51개와 독립 검증기 37개다. 기존 E2E 두 사례에는 정상 후행 모듈 응답을 추가했으며, 회사 수·검색·지역·상세·원문 링크·개인정보·요청 간격 기대값을 유지했다.

단위 검사에는 같은 이름을 쓰는 기존 매개변수 사례가 있어 파일·전체 이름 조합은 180개다. 수집된 203개 항목의 중복 횟수까지 JSON·JUnit 결과와 대조했다. 203개 고유 이름이라고 보고하지 않는다.

E2E 원본 HTML의 단계 기록 546개를 확인했다. 성공한 두 서버 준비 polling 안의 최초 실패 샘플 여섯 개는 그대로 남긴다. 이 샘플을 성공 응답이나 테스트 재시도로 바꾸지 않는다.

종료 후 조회한 소유 PID 83개는 남아 있지 않았다. 보존된 실제 시작 식별자는 24개이며, 실행 중 관측 수 114개를 모두 개별 시작 기록으로 간주하지 않는다. 자식 종료 callback 40개는 코드 0인 27개, Vitest의 `SIGTERM` 10개, 포트 부재 확인 명령의 코드 1인 두 개, 기본 서버의 `SIGKILL` 한 개로 구분한다. 세 esbuild 자식의 개별 종료 callback은 없으므로 그 종료 코드를 추정하지 않는다.

81.288초의 검사·정리 구간에서 전원 로그의 겹치는 기록 아홉 개는 모두 assertion 기록이며 Sleep·Wake·DarkWake 사건은 없었다. 실행 전후의 동일한 잠자기 방지 assertion과 종료 후 해제를 확인했다. 이 구간은 전체 wrapper의 83.882초보다 좁으며 시스템 전체의 연속 전원 감시를 뜻하지 않는다.

## 확인한 사용자 동작과 Cloudflare 경계

두 화면 크기 모두 가상 catalog의 회사·게시판 132개와 공고 7개를 확인했다. 새 두 회사의 가상 공고는 도시 미확인, 국가 `대한민국`, 수정 시각 미확인 상태를 유지했다. 검색과 아시아·태평양 필터, 유럽 제외, 공고 상세와 원문 링크가 동작했다. 네 상세 화면의 본문이 비어 있지 않고 측정된 가로 넘침이 없었으며 원문 지원 버튼이 표시됐다.

각 화면 검사에서 당근 요청 여섯 건의 URL과 최소 3초 간격을 확인했다. 이 요청은 모두 가상 응답이며 실제 출처 수집의 근거로 사용하지 않는다.

Worker 번들의 실제 입력 111개와 import 연결 360개에 Node 수집기, `parse5`, `entities`, `async_hooks`가 포함되지 않았다. Worker JavaScript는 944,332 bytes, gzip은 160,255 bytes로 이전 승인된 Worker와 동일하다. 정적 자산 367개와 기존 모듈·자산 한도도 확인했다. `wrangler deploy --dry-run`은 운영 배포가 아니다.
