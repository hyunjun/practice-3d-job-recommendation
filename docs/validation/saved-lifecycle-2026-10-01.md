## 실행 전 검토

테스트 도우미가 준비 자료를 읽는 동안 앱의 별도 연결에서 발생한 읽기까지 계수에서 빠질 수 있는 문제와, 한 번의 DOM 변경 통지에 포함된 중간 busy 상태를 놓칠 수 있는 문제를 발견해 보완했습니다. 실제 뒤로 이동의 관찰도 해당 이동·URL·문서와 연결된 네이티브 이벤트를 요구하도록 보완했습니다. 이벤트가 없거나 앞선 화면의 이벤트인 경우를 재로드로 단정하지 않습니다.

종료한 저장소 연결을 테스트의 후속 쓰기에 재사용하는 준비 오류도 수정했습니다. 실제 연결 종료와 늦게 완료된 읽기에 대한 기대값을 유지하고, 별도 쓰기 연결과 연결 수명마다 새로 여는 소유 연결을 사용합니다. 이는 실행 전 테스트 소스에서 발견한 사항이며 실제 제품 검사의 실패로 집계하지 않습니다. 저장 실패와 대기 입력이 동시에 있을 때의 재비교는 실제 저장 오류를 우선 안내하는 데 세 담당자가 동의했습니다. 실패한 입력은 단순 대기로 진행되지 않으므로, 기존 오류의 해결 방법을 알리고 선택·초안을 유지합니다.

검증·정리 도구 역시 독립 검토와 보완을 거쳐 세 담당자가 승인했습니다. 실제 실행자와 명령의 기록, 최종 선택한 실행의 전원 관찰, 보고서 첨부와 화면·네이티브 이벤트의 관계를 대조합니다. 삭제 전에 전체 대상 파일을 고정하고, 명시적으로 임시 자료로 분류되지 않은 파일은 Git 보존을 요구합니다. 이 도구 검토 자체를 앱 검증 통과로 보고하지 않습니다.

실행 뒤 정리 범위 검토에서 기존 공고 상태 E2E가 `.local/research/59/independent/runs`에 만든 실행 사본과 링크가 정리 목록에서 빠진 점을 발견했습니다. ## 첫 실행의 실제 근거 검토

개발 모드의 첫 실행은 251개 통과, 실패·건너뜀·불안정 통과·재시도 0개로 완료했습니다. 실제 저장 화면을 직접 확인하자 실패한 초안 화면 두 장에 메모·오류·재시도가 보이지 않았고, 320px 가져오기 화면의 선택한 파일 버전과 실제 뒤로 이동 화면의 메모·지원 상태도 캡처 밖에 있었습니다. 값·저장 결과에 대한 자동 검사는 통과했지만, 이 이미지로 요구한 영역의 시각 검토까지 완료했다고 보고할 수는 없습니다.

원본 보고서·이미지와 주 담당의 독립 판단을 보존했습니다. 당시 근거만으로 스크롤 위치·비활성 화면의 그리기·제품의 스크롤 동작 중 어느 것이 원인인지 단정하지 않았습니다. 다른 담당의 독립 관찰과 논의 후, 제품 내용을 숨기거나 바꾸지 않고 필요한 영역이 실제 화면 안에 있는지 명시적으로 검사하도록 보완했습니다.

세 담당자는 실패한 초안의 초점과 스크롤 위치를 화면 조정 전에 검사하는 데 동의했습니다. 실패 안내와 글꼴·레이아웃이 안정된 시점을 기준으로, 다른 탭의 변경과 복귀 신호 뒤에도 메모 입력의 초점·스크롤 위치·본문 내 위치가 유지되어야 합니다. 달라지면 검사를 실패로 남기고 원인을 논의합니다. 이 검사를 통과한 뒤에만 일반 스크롤로 검토 영역을 화면에 담으며, 입력·오류·쓰기 시도 수·종료 경고에 대한 기존 기대값도 유지합니다.

후속 소스 검토에서는 검사 자체의 세 가지 빈틈을 확인했습니다. 모달 안의 상대 위치만 비교하면 모달 전체의 화면상 이동을 놓칠 수 있고, 초점·스크롤 검사가 먼저 실패하면 측정 기록을 첨부하는 단계까지 도달하지 못했습니다. 또 처음 측정한 뒤에 생긴 가림이나 선택한 옵션의 표시값 변경을 후속 측정에서 실패로 처리하지 않았습니다. 세 담당자는 화면상 입력 위치 비교, 실패 경로의 부분 측정 기록 보존, 캡처 전후 각 시점의 가림·표시값 검사에 합의했습니다. 기존 기대값과 0.5 CSS 픽셀의 허용 오차는 유지합니다. 이 항목들은 실행 전 테스트 소스에서 확인한 사항이며, 실제 제품 검사 실패나 새 검증 통과로 집계하지 않습니다.

타입·단위 검사 실행 설명의 `360 test files / suites` 표기는 93개 실제 파일과 파일별 루트를 포함한 360개 전체 테스트 묶음(`aggregate suites`)을 구분하도록 정정 기록을 남겼습니다. 원본 Vitest 보고서에는 실제 파일 93개와 통과한 검사 3,308개가 있으며, 이 용어 정정은 제품·테스트 실패나 재실행 사유가 아닙니다.

## 실행 서비스의 중단 기록

첫 테스트 작성 호출은 제공자 안전 필터의 `[cyber]` 응답으로 종료됐습니다. 파일 수정과 테스트 실행은 없었습니다. 같은 세션에 소유한 로컬 앱의 가상 자료·저장 실패·브라우저 복귀 검사라는 범위를 명확히 전달했고, Fable은 해당 범위의 지원 가능 여부와 제한을 명시적으로 답했습니다. 모델·세션·보안 제한을 바꾸지 않고 테스트 작성을 재개했으며, 원래 중단과 범위 확인 기록을 함께 보존합니다. 이 중단은 제품 테스트의 실패나 테스트 통과로 세지 않습니다.

## 해석과 보존

직접 발생시킨 lifecycle 이벤트와 숨김 상태 검사는 실제 운영체제의 탭 전환 관찰과 구분합니다. 실제 뒤로 이동이 재로드였다면 BFCache 복원을 확인한 것으로 보고하지 않습니다. 이 단계는 같은 필드의 동시 편집 충돌 해결, 저장되지 않은 입력의 영구 보존, 새 공고 수집·현재 유효성·운영 부하 측정을 포함하지 않습니다.

최종 실행의 실제 뒤로 이동은 두 모드 모두 서로 다른 문서 표식과 신뢰할 수 있는 `pageshow.persisted=false`로 재로드가 확인됐습니다. 돌아온 화면의 메모는 `Changed while away`, 지원 상태는 `지원 완료`였습니다. 실제 `PerformanceObserver`는 각각 navigation 항목 하나를 수집했고, `back_forward`와 `broadcastchannel-message` 진단을 기록했습니다. 이 값은 BFCache 복원 성공을 뜻하지 않습니다.

실패한 초안의 측정 기준 시점 T0는 실패 안내와 레이아웃이 안정된 뒤입니다. 두 너비·두 모드 모두 이때 입력란 일부가 이미 하단 고정 영역 뒤에 있었고, 다른 탭의 변경과 복귀 신호 뒤 측정한 T1·T2에서도 초점·위치·스크롤은 같았습니다. 이후 일반 스크롤로 초안·오류·복구 동작 전체가 보이는 것을 확인했습니다. 이 값들은 측정 시점의 일치를 보여주며, 시점 사이의 일시적인 스크롤·레이아웃 변경까지 배제하지 않습니다. 오류가 처음 발생할 때 자동으로 입력란이 드러나는지나 T0 이전 위치의 원인도 확인하지 않았습니다. Astra가 후속 보고서의 연속적인 무변화로 읽힐 수 있는 표현을 지적했고, 최종 결론을 실제 측정 시점과 순수 위치 차이의 범위로 한정했습니다. 이를 캡처만의 문제나 수정된 제품 결함으로 단정하지 않습니다.

가져오기 화면은 복귀 전후 2페이지 유지 검사 뒤 사용자가 이전 페이지로 이동한 상태를 촬영했습니다. 이미지가 2페이지 유지를 직접 보여준다고 해석하지 않습니다. 상세 제목과 하단 내용은 같은 공고 상태의 두 화면으로 확인하며, 설명 펼치기·스크롤 전후의 전체 레이아웃이 같다고 주장하지 않습니다. 화면 캡처와 각 측정 시점의 일치는 모든 중간 프레임의 연속적인 안정성이나 실제 모바일 기기 검증을 대신하지 않습니다.
