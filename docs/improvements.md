# ORBIT 개선 기록

개선별로 확인한 문제, 참고 자료, 반영한 동작과 검증을 기록합니다. 원본 이력서와 공개 공고 전체 응답은 이 문서나 저장소에 포함하지 않습니다.

## 01 · 채용 조건과 원문 근거 — 2026-09-19

### 확인한 문제

- Datadog의 `Time Type: Full time`과 Anthropic의 `Location Type: On-Site`가 기존 필드 목록에서 누락되어 있었습니다.
- 직무·지원자에 따라 제한되는 비자 지원 정책이 모두 미확인으로 분류되어, 지원 문구가 있는 공고를 따로 찾기 어려웠습니다.
- Cloudflare의 수출 통제 안내에 있는 `without sponsorship for an export license`가 취업 비자 미지원으로 오분류되었습니다.
- `Full time`을 정규직으로 표시해 근무 시간과 계약 형태를 혼동할 수 있었습니다.
- 화면의 판별 결과에서 실제 근거 문장으로 연결되는 경로가 없었습니다.

### 반영한 동작

- 알려진 공고별 메타데이터를 우선하고, 필요한 경우 해당 직무를 직접 설명하는 문장만 사용합니다. 일반적인 회사 복지, 유연근무 소개, `2-Flexible`처럼 뜻이 명확하지 않은 내부 값은 추정에 사용하지 않습니다.
- 비자 조건을 지원 명시·조건부·지원 없음·미확인으로 분리했습니다. 기존의 조건부 제외 필터를 유지하면서 조건부 포함 선택지를 추가했습니다. 서로 상충하는 문구는 지원 가능으로 단정하지 않습니다.
- 수출 허가 스폰서십을 취업 비자 정책에서 제외했습니다.
- 비자·근무·고용 형태의 근거 문구와 출처 종류를 공고 상세에서 펼쳐 볼 수 있습니다. 저장한 공고에도 근거가 함께 보존되며, 예전에 저장한 공고도 계속 읽을 수 있습니다.
- 풀타임·파트타임·계약직·인턴·임시직을 구분합니다. 풀타임을 정규직 계약으로 단정하지 않습니다.
- 데이터 화면에 조건별 확인 건수를 추가했습니다.
- 모바일의 조건 입력란을 한 열로 배치해 비자 지원 필터의 조건부 포함·제외 문구가 잘리지 않도록 했습니다.
- 조건 추출을 `server/job-facts.ts`로 분리해 다른 채용 게시판 수집기에서도 재사용할 수 있게 했습니다.
- Greenhouse 급여 범위의 공식 필드명인 `currency_type`을 읽도록 보완했습니다.

### 실제 데이터 확인

2026-09-19 03:56 UTC에 조회한 10개 게시판의 동일한 응답으로 이전 동작과 개선 동작을 대조했습니다. 이후 04:08 UTC에 앱의 실제 API에서도 10개 게시판이 모두 정상 조회되는 것을 확인했습니다.

| 항목 | 이전 | 개선 후 |
| --- | ---: | ---: |
| 지도·원격 탐색에 포함된 개발 공고 | 707 | 708 |
| 조건부 비자 지원으로 분류 | 0 | 182 |
| 비자 미지원으로 분류 | 115 | 0 |
| 근무 형태 미확인 | 427 | 290 |
| 고용 형태 미확인 | 633 | 560 |

추가된 1개 공고는 공고별 원격 메타데이터를 읽게 되면서 도시 좌표가 없어도 원격 탐색에 포함된 경우입니다. 비자 미지원 115개는 수출 허가 문구에 의한 오분류였으며, 개선 후에는 비자 미확인으로 남깁니다. 수치는 이 시점의 수집 범위와 분류 결과이며 채용 시장 전체 규모나 분류 정확도를 뜻하지 않습니다.

### 참고 자료

- [Greenhouse Job Board API](https://developers.greenhouse.io/job-board.html): 공개 조회, `content=true`, 공고별 `metadata`·`offices`, 급여 범위의 `currency_type`을 확인했습니다.
- [Ashby Public Job Posting API](https://developers.ashbyhq.com/docs/public-job-posting-api): `workplaceType`, `employmentType`, `secondaryLocations`, 보상 항목별 통화·기간 구조를 확인했습니다.
- [Lever Postings API](https://github.com/lever/postings-api): `categories.commitment`, `workplaceType`, `salaryRange.interval`을 확인했습니다.

이번 개선에서 실제 수집에 연결한 소스는 기존 Greenhouse 게시판입니다. Ashby와 Lever는 수집 범위를 확장할 때 사용할 구조화된 정보와 공통 데이터 계약을 검토한 자료입니다.

### 검증

- 단위 검사: 조건부·부정·상충 문구, 수출 허가와 취업 비자의 구분, 게시판 메타데이터의 우선순위, 일반 회사 소개의 오인 방지, 계약 형태, 급여 필드, 비자 필터.
- 브라우저 검사: 조건부 포함·제외 선택, 원문 근거 펼치기, 공고 저장 후 새로고침, 저장된 근거 복원, 접근성.
- 단위 검사 38개, 기존 브라우저 시나리오 11개와 새 시나리오 1개가 통과했습니다. 실제 공개 공고를 사용한 배포 빌드에서도 데스크톱·모바일의 근거 표시, 가로 넘침과 브라우저 오류를 확인했습니다.

### 이어서 확인할 항목

- 공개 데이터 모드, 검색 조건과 선택 도시의 재방문 복원.
- 회사별 조회 실패 시 이전 데이터를 보존하는 수집 구조와 공고 변경·마감 이력.
- Ashby·Lever 수집기와 도시·회사 범위의 다양성.
- 원격 근무지의 `CAN` 같은 국가 코드와 구조화된 지역 정보 정규화. 현재 해석하지 못한 지역은 지원 가능으로 추정하지 않습니다.
- 경력 차이, 필수·우대 기술, 시민권·취업 허가 조건을 반영한 추천 집계와 평가용 공고 집합.
