검토 대상은 HEAD `d96367ba9e06ad32737250a482c662e11b7881be`에 대한 다섯 소스 파일의 전체 변경과 새 `src/lib/dialog-visibility.ts` 765줄이다. 기존 소스 전체나 모든 대화상자를 다시 감사한 결과는 아니다. 검토한 현재 여섯 파일의 정확한 내용은 `root-delta-independent-primary-01/manifest.json` SHA256 `2d1d2082f38eeeaead2d7f82a04f403a5b364acb3472fbc904ee1995ccaaf3f3`에 연결한다. 변경 diff는 40774바이트 / `2068f20b91aefbedb179c81578357d214c8b004b6d38e2c3c3d98c7ac287f5f9`이다. 전체 22개 미완료 파일의 보호와 별도로, 이 보안 판단의 소스 범위는 여섯 파일이다.

Main, Astra, Fable은 각각 첫 의견을 보존한 뒤 서로의 판단을 비교한다. Main과 Astra는 원본 여섯 파일의 해시를 직접 확인했다. Fable은 제공된 스냅샷을 해시로 확인하고 원본의 일부 내용과 비교했다. Fable이 원본 파일을 직접 전부 해시로 확인한 것으로 보고하지 않는다. 이 문서 자체는 합의 제안이며, 세 참여자의 같은 해시에 대한 실제 승인이 모이기 전에는 전원 합의가 아니다.

검토한 변경에서 새로 추가된 정보 전송·지속 저장·문자열의 HTML/코드 실행·외부 이동 경로 또는 기존 저장 권한 우회를 뒷받침하는 공격 경로는 확인하지 못했다. 이는 해당 변경과 조사한 호출부에 한정한 결과이며, 공격 경로가 존재하지 않는다는 증명이나 전체 서비스의 안전 판정은 아니다. 정해진 API 이름이 검색되지 않았다는 사실만으로 이 결론을 대신하지 않는다.

새 helper는 문서 수준 입력 이벤트를 받아 로컬 포커스·스크롤·레이아웃 상태를 관리한다. 요소 참조, 선택 범위, 소유 대화상자와 동작 ticket 외에 원래 Event 객체를 구독자에게 전달하고, footer의 textContent를 basisText로 보관한다. 키·입력·조합 이벤트는 종류에 따라 입력 내용을 포함할 수 있으므로 이를 모두 “내용 없는 메타데이터”라고 부르지 않는다. 조사한 현재 경로에서는 이 관찰 내용을 새 로그·전송·저장소로 보내는 sink를 찾지 못했다. 문서 전체의 상호작용을 관찰하는 범위가 추가되었다는 사실과 실제 외부 공개가 입증되지 않았다는 사실을 함께 기록한다.

이벤트 리스너의 passive 설정은 해당 리스너에서 preventDefault로 기본 동작을 취소할 수 없다는 뜻이다. 그 설정만으로 포커스·스크롤 등 다른 동작이 사용자 입력에 영향을 주지 않는다고 보장할 수는 없다. 동작 ticket의 scope·epoch·stack·소유자 수명·연결·열림 검사는 뒤늦은 복구가 새로운 상호작용을 침범하지 않게 하려는 소스상의 보호 장치다. 실제 브라우저 이벤트 순서, IME, 선택, 터치, 중첩 대화상자, 닫힘·다시 열림에서의 결과는 별도 검증 대상이다.

helper가 CSSOM에 쓰는 두 속성은 측정·계산한 값을 px 문자열로 만드는 경로이며, data 속성은 고정 이름과 'true' 값을 사용한다. footer 문자 내용과 공고·메모의 길이는 요소 크기를 통해 계산 결과에 간접적으로 영향을 줄 수 있다. 따라서 “사용자 내용은 style 값에 전혀 도달하지 않는다”는 표현은 사용하지 않는다. 조사한 변경에서는 임의의 사용자 문자열이 그대로 속성 이름·CSS 구문·선택자로 삽입되는 경로를 확인하지 못했다. jobId가 포함되는 기존 선택자는 CSS.escape를 유지한다. 이 점검에서는 실제 정책과 브라우저별 CSP/CSSOM 적용 결과를 검증하지 않았다.

SavedDataDialog의 변경 호출부에는 파일 크기 검사, 비동기 읽기 결과의 유효성 검사, parseSavedImport, canWrite·stale·선택·개수 제한이 유지된다. 가져오기·복구 삭제·다운로드는 기존 저장소와 내보내기 함수를 계속 사용한다. 알림과 복구 대상에 연결한 focus ticket은 저장 권한을 대신하지 않는다. ProfileDialog의 변경은 숨겨진 파일 입력을 순차 Tab 이동에서 제외하는 속성이다. 이 변경이 이력서 추출기나 저장 거래 전체를 다시 검증했다는 뜻은 아니다.

소스에는 구독·컨트롤러 해제, observer 해제, 애니메이션 프레임 취소, 리스너 제거, 이전 세대 작업의 유효성 검사와 자신이 마지막으로 쓴 값만 복원하는 처리가 있다. 관찰 대상 Set은 다음 측정에서 불필요한 요소를 제외한다. 그러나 이 정적 관찰만으로 메모리 유지량이나 유지 시간이 제한되었다고 단정하지 않는다. 특히 revealRestoredOpener의 임시 리스너는 예정된 animation-frame 콜백에서 제거되며, 프레임이 멈춘 동안의 수명과 DOM 참조 유지 시간은 측정하지 않았다. 누수나 공격 가능성이 입증되었다는 주장도 아니다.

레이아웃 변경의 입력 영역·레이블·확인 버튼 접근성과 포커스 복구, observer 및 계산 스타일 읽기의 비용, 긴 메모·최대 페이지 구성의 응답성, 브라우저 API 지원 실패의 영향은 실행 결과가 없는 상태다. 읽지 않은 다른 대화상자나 기존 저장소 내부를 “보안과 무관하다”고 배제하지 않는다. 범위를 넘는 전체 정확성·정보 비유출·성능 주장은 하지 않는다.

Fable은 기존 미완료 E2E 파일 일곱 개와 helper 여섯 개의 목록, 검사 제목 및 일부 요청·저장소 관련 문자열을 조사했다. 이는 해당 검사의 전체 의미 검토나 실행 통과가 아니다. 새 파일에서 확인한 요청 경로와 저장소 접근은 자료 준비와 응답 대체였고, 그 조사만으로 상호작용 중 정보 유출을 감시하는 검사가 있다고 확인하지는 못했다. 뒤늦은 결과가 새 입력을 침범하지 않는지, 확인 동작과 안내를 계속 사용할 수 있는지, 정보가 의도하지 않은 요청·저장으로 나가지 않는지, 종료 후 동작이 남지 않는지처럼 관찰 가능한 결과가 유용한 검증 대상이다. API 이름이나 내부 구현을 그대로 검사하는 정적 guard만으로 이를 대신하지 않는다. 여기서 새 테스트 행렬·임계값을 확정하거나 기존 필수 검사를 면제하지 않는다.
