# 관측 기록과 채용 분포

공개 데이터 화면의 **관측 기록과 채용 분포**에서 수집 대상, 날짜별 집계와 회사·지역·직무·근무 형태·기술의 분포를 확인할 수 있습니다. 프로필·검색·저장 공고와 무관한 공개 게시판 표본입니다.

기록을 읽거나 날짜·분포 항목을 바꿀 때 외부 채용 사이트를 조회하지 않습니다. 기존의 본문 수집이 끝나면 그 결과에서 집계하며, 게시 ID만 확인하는 경로는 새로운 본문 관측을 만들지 않습니다.

## 기록의 단위

UTC 날짜, 당시의 회사·게시판 구성, 해석 기준을 묶음의 식별자로 사용합니다. 같은 날에는 마지막 시도와 마지막 완전한 집계를 보존합니다. 오후 조회가 실패해도 같은 날 오전에 완성한 집계를 부분 결과나 0개로 바꾸지 않습니다.

완전한 집계는 다음을 모두 충족해야 합니다.

- 설정된 모든 게시판의 마지막 본문 조회가 성공했습니다.
- 각 게시판의 전체 공개 ID와 공고·출처·조회 시각이 일치합니다.
- 이전 캐시에서 본문을 보존하지 못한 기타 근무지 공고가 없습니다.
- 집계의 기준 시각에서 모든 게시판의 정상 자료가 30분 미만입니다.

기준 시각은 해당 시도에 포함된 실제 게시판 조회 시각 중 가장 늦은 시각입니다. 회사별 조회는 순차적으로 진행될 수 있으므로 같은 순간의 시장을 측정했다는 뜻은 아닙니다. 캐시를 다음 날 읽었다는 이유로 원래 조회 시각을 갱신하지 않습니다.

전체 게시판이 정상적으로 빈 목록을 반환하면 0개라는 관측이 됩니다. 조회하지 않은 날, 응답 실패, 불완전한 목록은 0개가 아닙니다. 이 기능이 매일 정해진 시간에 수집하는 스케줄러를 추가하지는 않습니다.

## 비교 조건

서로 다른 두 날짜의 완전한 집계가 있고 회사·제공자·게시판·Lever 서비스 지역과 분류 기준이 모두 같을 때만 일반 공고 수의 차이를 표시합니다. 직전 **관측 날짜**와 비교하며 중간에 기록이 없는 날짜를 채우지 않습니다.

회사 이름의 표시만 바뀐 것은 구성 변경으로 보지 않습니다. 회사 추가·삭제, 게시판 교체, 지역 변경 또는 해석 기준 변경은 별도 묶음입니다. 새 회사를 수집한 증가분이나 분류 규칙 때문에 제외된 공고를 시장의 성장·감소로 표시하지 않습니다.

새 본문 스냅샷에는 `observationMethod`를 보관합니다. 이전 캐시에 당시 기준이 없거나 현재 기준과 다르면 원래 날짜의 분포를 표시할 수 있지만 `comparable: false`로 두어 날짜 비교에서 제외합니다. 저장된 과거 집계에 최신 분류를 다시 적용하지 않습니다.

`OBSERVATION_METHOD`는 직군·세부 직무·자격·원격 범위·고용 형태·모집 유형의 버전을 포함합니다. 지역 해석, 기술 추출이나 집계 방식처럼 해당 버전으로 포착하지 못하는 동작을 바꿀 때는 선두 관측 버전도 올려야 합니다.

공고 수의 차이는 신규 채용·채용 종료 건수나 채용 인원이 아닙니다. 회사 게시판 사이에 중복 게시된 같은 포지션을 식별하는 기능도 아니므로 개별 제공자의 게시 ID를 관측 단위로 사용합니다.

## 분포와 분모

| 항목 | 집계 기준 |
|---|---|
| 공개 목록 전체 직군 | 정상 본문 수집에 사용한 전체 공개 ID 수 |
| 개발·컴퓨팅 후보 | 현재 탐색 직군에 포함되는 고유 공고 수 |
| 일반 채용 공고 | 위 후보에서 명시적으로 확인된 인재풀·관심 등록을 제외 |
| 인재풀·관심 등록 | 별도 표시하며 아래 모든 분포의 분모에서 제외 |
| 회사 | 일반 공고 수와 가장 많은 회사·상위 최대 5개 회사의 비중 |
| 근무 지역 | 공고별 확인된 근무 국가의 지역. 복수 지역은 각 지역에 한 번씩 포함 |
| 원격근무 | 근무 지역 분포에서 별도 구분. 지원자의 거주 가능 국가를 오피스 위치로 사용하지 않음 |
| 지역 미확인 | 전체 또는 일부 위치가 불명확하거나 충돌한 경우. 확인된 다른 지역과 겹칠 수 있음 |
| 개발 직무 | 근거가 있는 세부 직무별 집계. 복수 직무는 각각 포함하고 미확인도 표시 |
| 근무 형태 | 원격·하이브리드·오피스·미확인을 구분 |
| 기술 | 기술별 언급·필수·자격·우대 항목을 별도로 세고 같은 공고 안에서는 각 항목을 중복 제거 |

지역·직무의 합계는 복수 분류 때문에 분모를 넘을 수 있습니다. 회사·근무 형태는 일반 공고를 중복 없이 나눕니다. 일반 공고가 0개이면 비중을 계산하지 않습니다.

필수 항목의 “Python 또는 Go”는 두 기술 모두 **필수 항목에 포함**으로 셉니다. 각 기술이 단독으로 반드시 필요하다는 뜻이 아닙니다. 기술 언급은 업무 설명도 포함하며, 필수·자격·우대 항목은 서로 겹칠 수 있습니다. 언급 공고 수가 많은 기술 100개를 보관하고 화면에는 상위 20개를 표시합니다.

좁은 화면에서 기술 표를 좌우로 넘길 때도 기술 이름은 첫 열에 남습니다. 표에 키보드 초점을 둔 뒤 방향키로 나머지 항목을 읽을 수 있습니다.

현재 버전은 날짜를 고르고 각 분포를 독립적으로 보는 기능입니다. 지역과 직무를 교차 필터링한 과거 통계, 기술 조합, 보상 분위수, 외부 채용 지수는 포함하지 않습니다.

## API와 보존

`GET /api/observations`는 현재 설정 범위의 기록을 읽습니다. 공고 ID·프로필·메모를 입력으로 받지 않으며 외부 수집을 시작하지 않습니다. 최초 접근에서는 기존 본문 캐시를 원래 시각으로 관측 파일에 기록할 수 있습니다. 본문 캐시 자체는 이 읽기로 저장하거나 갱신하지 않습니다.

응답 버전은 1이며 현재 구성·분류 기준, 날짜별 마지막 시도와 완전한 집계, 비교에서 제외한 다른 묶음의 요약, 저장 상태를 포함합니다. 날짜·분포 선택은 브라우저에서 처리합니다. 데이터 화면에서 이 부분을 펼쳤을 때만 기록 API를 읽고, 열린 상태에서 본문 수집이 끝나면 다시 읽습니다.

관측 파일은 본문 캐시 옆의 `observations-v1/<본문 캐시 파일명>`에 저장합니다. 기본 경로는 `.local/observations-v1/public-board-cache-v5.json`입니다. 실제 자료와 함께 Git에서 제외됩니다. 파일에는 집계 숫자와 공개 회사·게시판 식별자·조회 시각을 담으며 공고 본문, 지원 URL, 사용자 프로필·메모·저장 ID는 담지 않습니다.

최근 90개 UTC 날짜 범위에서 최대 4개의 구성·기준 묶음을 유지합니다. 더 오래된 날짜와 추가 묶음은 다음 저장 시 제거됩니다. 파일은 최대 16 MiB이며 임시 파일을 완성한 뒤 원자적으로 교체합니다.

읽기 오류나 잘못된 형식의 파일을 빈 정상 기록으로 덮어쓰지 않습니다. 해당 프로세스에서는 새 기록 저장을 중단하고 화면에 오류를 표시합니다. 파일을 복구한 뒤 서버를 재시작하면 다시 읽습니다. 용량 초과·쓰기 오류 때에는 마지막으로 저장된 기록을 유지하고 오류를 표시하며 다음 본문 수집에서 저장을 다시 시도합니다. 본문 수집·탐색은 관측 저장 오류와 별도로 계속할 수 있습니다.

단일 서버 프로세스의 로컬 기록입니다. 서버 여러 대가 같은 파일에 동시에 쓰는 운영을 지원하는 저장소나 분산 잠금은 포함하지 않습니다.

## 관련 검사 실행

단위 검사는 숫자·분모·날짜·구성 변경·저장 실패와 수집 경로를 확인합니다.

```bash
npx vitest run tests/unit/catalog-observations.test.ts tests/unit/catalog-observations-cache.test.ts
```

E2E는 가상 회사의 응답과 별도 캐시·서버를 사용합니다. 1440px·320px에서 날짜·분포 선택, 실패 후 복구, 저장 기록·개인 조건 보존, 키보드·접근성을 검사합니다. 확인용 서버를 빌려 쓰지 않습니다.

```bash
npx playwright test --config=tests/fixtures/catalog-observations.playwright.config.ts
```

프로덕션 검사는 먼저 현재 소스를 빌드합니다.

```bash
npm run build
ORBIT_OBSERVATIONS_MODE=production npx playwright test --config=tests/fixtures/catalog-observations.playwright.config.ts
```

결과는 `.local/research/60/independent/`에 저장합니다. `ORBIT_OBSERVATIONS_RUN`으로 실행 이름을 구분할 수 있습니다.
