# 브라우저 저장 기록

저장한 공고·메모·지원 상태를 같은 브라우저와 주소에서 이어 쓰기 위한 로컬 저장소입니다. 외부 계정이나 서버 저장 API를 사용하지 않습니다.

## 저장 위치

| 데이터 | 위치 |
| --- | --- |
| 공고 스냅샷·회사·메모·지원 상태·저장일 | IndexedDB `orbit-saved-opportunities`, 버전 1의 `records` |
| 저장 순서와 이전 완료 표시·복구용 원본 | 같은 데이터베이스의 `meta` |
| 프로필·탐색 조건·도시 비교 | 기존 `orbit.v1.*` localStorage 항목 |
| 이전 형식의 공고 목록 | 이전이 완료될 때까지 `orbit.v1.saved` |

`records`는 공고 ID를 키로 사용하며 `{ id, order, record }`를 저장합니다. `record`는 기존 `SavedJob` 형식이고, `order`는 저장할 때 트랜잭션 안에서 발급합니다. 메모를 수정해도 순서는 바뀌지 않습니다. 삭제를 실행 취소하면 목록 맨 앞에 복원하지만 원래 저장일은 유지합니다.

저장 한도는 500개입니다. 읽을 수 없는 기존 항목도 용량 계산에 포함하며, 여러 탭이 동시에 추가해도 트랜잭션 안에서 다시 한도를 확인합니다. 실제 브라우저 저장 용량은 브라우저·기기·사용 환경에 따라 다릅니다.

## 이전과 복구

1. 이전 localStorage 값을 읽고 개별 공고를 검증합니다. 한 항목이 잘못되어도 다른 정상 공고를 버리지 않습니다. 같은 ID는 첫 번째 항목을 사용합니다.
2. 정상 공고, 원래 목록 순서, 이전 완료 표시를 한 트랜잭션에서 기록합니다. 형식 오류·중복·한도 초과·기존 데이터와의 충돌이 있으면 이전 문자열 전체를 복구용 원본으로 함께 보관합니다.
3. 트랜잭션이 완료되고 localStorage 값이 처음 읽은 값과 같은 경우에만 이전 키를 제거합니다. 저장 실패·중단 시 이전 키는 남습니다.
4. 이전 완료 후 같은 원본이 다시 나타나도 최신 메모를 덮어쓰지 않습니다. localStorage에 남거나 다시 생긴 값은 이미 이전한 내용과 같아도 별도 사본으로 안내합니다.

기존 IndexedDB의 읽을 수 없는 항목도 그대로 남깁니다. 그 ID의 추가·수정·삭제로 원본을 덮어쓰지 않으며 정상 항목은 계속 사용합니다. 이전 원본의 SHA-256 값은 같은 이전 작업의 반복을 확인하기 위해 브라우저 안에서만 계산합니다.

복구 파일은 `orbit-saved-recovery-날짜.json`이며, 원래 localStorage 문자열 또는 읽을 수 없는 데이터베이스 항목을 담습니다. 현재 목록 전체의 백업과는 별도입니다. 이전 원본 전체에는 정상 공고와 메모도 포함될 수 있으므로 현재 목록에서 해당 공고를 삭제해도 원본에 남을 수 있습니다. 내려받은 복구 파일은 아래 가져오기 절차로 검토할 수 있습니다.

## JSON 백업과 가져오기

저장 화면의 **기록 백업·복원**에서 현재 기록을 내보내거나 파일을 선택합니다. 백업은 공고 스냅샷·회사·메모·지원 상태·저장일을 담은 일반 JSON 파일이며, 현재 화면의 저장 대기 중 입력도 포함합니다. 프로필·이력서·탐색 조건·도시 비교·별도로 보관한 복구 원본은 포함하지 않습니다. 복구 원본은 해당 화면에서 각각 내려받습니다.

### 파일 형식과 검증

| 입력 | 형식 |
| --- | --- |
| 현재 목록의 백업 | `format: "orbit-saved-backup"`, `version: 1`, `exportedAt`, `includesUnsavedChanges`, `records: SavedJob[]` |
| 이전 버전부터 제공한 복구 파일 | `format: "orbit-saved-recovery"`, `version: 1`, `sources` |
| 이전 localStorage의 목록 | `SavedJob[]` JSON 배열 |

백업의 `exportedAt`은 파일을 만든 시각입니다. 각 공고의 원래 조회 시각·저장일을 바꾸지 않습니다. `includesUnsavedChanges`는 내보낼 때 저장 대기 중인 변경이 있었음을 나타내며, 복원 후에는 선택한 기록 전체를 정상 저장합니다. CSV는 공고 스냅샷의 복원 형식으로 사용하지 않습니다.

파일당 최대 50MiB(`50 × 1024 × 1024`바이트), 검토할 항목 최대 5,000개를 허용합니다. 파일 선택기의 `accept`는 안내이므로 파일명·MIME만 신뢰하지 않습니다. `File.size`를 읽기 전에 확인하고 JSON·버전·항목 수·각 `SavedJob` 스키마와 회사 ID의 일치를 검증합니다. 해석 가능한 정상 항목을 제시하고 읽을 수 없는 항목·원본 묶음의 수를 표시합니다. 지원하지 않는 형식이나 버전, 파일 한도 초과는 반영하지 않습니다.

복구 파일의 이전 문자열은 배열로 다시 해석합니다. 데이터베이스 래퍼의 순서 값이 잘못되었더라도 내부 공고와 ID가 유효하면 복원 후보로 제시합니다. 원본 파일은 수정하지 않습니다. 파일을 읽거나 비교할 때 서버에 전송하지 않으며, 메모·공고 본문·JSON은 실행 가능한 HTML 대신 텍스트로 표시합니다.

### 선택과 충돌 처리

1. 검토 시작 시 현재 기록·점유 수·읽을 수 없는 ID를 고정합니다. 새 공고만 남은 저장 한도 안에서 기본 선택하고 기존 기록은 유지합니다.
2. 서로 다른 중복 기록은 한 공고의 여러 후보로 보여줍니다. 기존 기록의 대체 후보를 바꾸면 해당 공고의 선택을 해제합니다. 동일한 기록과 원본을 읽을 수 없는 기존 ID는 선택할 수 없습니다.
3. 공고를 20개씩 보여주며 새 공고·내용이 다른 공고·선택한 공고 등으로 좁힐 수 있습니다. 기존 값과 파일의 메모·지원 상태·저장일·공고 내용을 비교한 뒤 대체할 공고를 직접 선택합니다.
4. **현재 기록으로 다시 비교**하면 최신 목록을 읽고 기존 기록을 바꾸는 선택을 초기화합니다. 다른 탭의 변경으로 미리보기가 오래되면 이 절차를 요구합니다.
5. 반영할 때 `records`·`meta`의 한 readwrite 트랜잭션에서 선택한 각 ID의 현재 값이 검토 당시 값과 같은지, 새 공고가 여전히 없는지 다시 확인합니다. 읽을 수 없는 항목을 포함한 500개 한도도 확인합니다. 불일치·용량 부족·트랜잭션 중단 시 전체 선택을 취소하며 일부만 반영하지 않습니다.

새 공고는 파일 안의 순서를 유지해 기존 목록 앞에 추가합니다. 대체한 공고는 목록의 기존 위치를 유지하며 내용은 선택한 파일의 기록 전체로 바뀝니다. 조회·저장 시각은 기록에 포함된 값을 유지합니다. 이 동작을 위해 데이터베이스 버전이나 저장소를 추가하지 않았습니다.

현재 탭에 저장 대기 중 입력이나 저장 오류가 있으면 가져오기·원본 삭제를 막고 먼저 재시도하거나 현재 내용을 백업하도록 안내합니다. 반영 중에는 해당 탭의 다른 저장 변경을 받지 않습니다. 트랜잭션 실패 후 파일과 선택은 유지하고, 현재 값이 달라졌거나 한도가 변했으면 다시 비교하게 합니다. 커밋은 성공했지만 목록 재조회가 실패한 경우에는 저장 성공과 재연결 필요를 구분해 표시합니다.

## 보관 원본 정리

**따로 보관한 원본 관리**에서 각 보관본을 내려받거나 삭제할 수 있습니다. 다운로드만으로 원본을 지우지 않습니다. 삭제 대상과 범위를 확인한 뒤 반영하며 현재 정상 공고 목록·다른 보관본·이미 내려받은 파일은 유지합니다.

| 보관본 | 삭제 전 확인과 범위 |
| --- | --- |
| 이전 목록의 보관 원본 | `meta`의 원래 문자열이 검토한 값과 같은지 트랜잭션 안에서 확인하고 해당 원본만 삭제. 이전 완료 표시는 유지 |
| 읽을 수 없는 저장 항목 | 해당 묶음의 모든 래퍼가 검토한 값과 같고 여전히 읽을 수 없는지 확인한 뒤 한 트랜잭션에서 삭제. 새 정상 기록이나 바뀐 원본은 삭제하지 않음 |
| 이전 형식의 브라우저 사본 | localStorage 값이 검토한 문자열과 같은지 삭제 직전에 확인하고 해당 키만 제거 |

원본이 달라지면 삭제하지 않고 갱신된 원본을 다시 검토하도록 안내합니다. 읽을 수 없는 ID를 정리한 후에는 파일을 다시 비교해 해당 공고를 복원할 수 있습니다. 이미 이전한 localStorage 사본이 다시 나타나도 이전 완료 표시 때문에 최신 기록을 자동으로 덮어쓰지 않습니다.

localStorage에는 여러 프로세스 사이의 잠금·원자적인 비교 후 삭제가 보장되지 않습니다. 따라서 이전 형식의 브라우저 사본을 정리할 때에는 **이전 버전의 다른 ORBIT 탭을 닫으라**고 안내합니다. 그 탭이 계속 실행 중이면 확인과 삭제 사이에 값을 바꾸거나 사본을 다시 만들 수 있습니다. IndexedDB에 보관한 원본을 지워도 별도의 localStorage 사본은 남을 수 있으며 각각 표시하고 정리합니다.

## 저장 상태와 재시도

화면의 현재 입력과 마지막으로 저장에 성공한 목록을 분리합니다.

| 상태 | 동작 |
| --- | --- |
| 불러오는 중 | 첫 읽기가 끝나기 전에는 저장 변경을 받지 않으며 탐색은 계속 제공 |
| 저장 중 | 현재 입력을 즉시 표시하고 공고별 변경을 순서대로 처리 |
| 저장 완료 | 개별 요청의 성공이 아니라 트랜잭션 `complete` 이후에 표시 |
| 저장 실패 | 마지막 입력과 대기 중인 변경을 유지하고 재시도·현재 내용 CSV·JSON 백업을 제공 |

같은 공고에 대한 대기 중 메모·지원 상태 변경은 합칩니다. 이미 진행 중인 쓰기는 건드리지 않습니다. 재시도는 저장소를 다시 읽은 뒤 보관한 변경을 적용합니다. 사용자가 이후 제거한 공고의 실패한 수정은 폐기하며 삭제를 먼저 처리하므로, 한도에 걸린 추가를 다시 시도할 때 공간을 확보할 수 있습니다.

다른 탭에서 삭제한 공고를 수정하려 하면 메모를 현재 탭에 남기고 오류를 안내합니다. 사용자가 재시도를 선택하면 그 메모와 원래 공고 스냅샷을 복원합니다. 읽기 자체가 실패한 경우와 정상적인 빈 저장 목록은 구분합니다.

아직 저장하지 못한 변경이 있을 때만 `beforeunload` 처리기를 등록합니다. 브라우저의 탭 닫기 안내는 특히 모바일 종료에서 항상 실행되는 기능이 아니므로, 저장 완료 표시 또는 JSON·CSV 내보내기로 보관 여부를 확인해야 합니다. 브라우저가 종료되면 메모리에만 있던 입력은 복구할 수 없습니다.

## 여러 탭과 보관 범위

`BroadcastChannel`에는 저장 내용 대신 `changed` 알림만 보냅니다. 다른 탭은 같은 IndexedDB를 다시 읽습니다. 처리 중인 변경이 있으면 새 목록으로 현재 입력을 덮어쓰지 않고 로컬 처리가 끝난 뒤 다시 읽습니다. 이전 버전 탭의 localStorage 변경도 감지합니다.

수정은 현재 데이터베이스의 해당 공고에 변경한 필드만 적용합니다. 한 탭의 메모와 다른 탭의 지원 상태는 합칠 수 있지만, 같은 필드의 동시 편집은 마지막에 완료된 쓰기가 남습니다. 공동 편집이나 충돌 해결 기능은 아닙니다. BroadcastChannel을 지원하지 않는 환경에서는 저장은 가능하지만 다른 탭의 변경 알림은 제공되지 않습니다.

브라우저 저장은 기본적으로 best-effort입니다. 사이트 데이터 삭제·브라우저의 저장 공간 회수·비공개 창 종료로 공고와 복구 원본이 함께 없어질 수 있습니다. `localhost`와 `127.0.0.1`, 다른 포트와 다른 브라우저는 별도 저장소입니다. JSON 백업으로 기록을 옮길 수 있으며 계정 동기화는 제공하지 않습니다. 프로필 삭제는 공고·메모·복구 원본·도시 비교를 삭제하지 않습니다.

## 검증

`fake-indexeddb`는 단위 검사에만 사용하며 실제 앱은 네이티브 IndexedDB를 사용합니다. 이전 중단, 성공한 `put` 뒤의 트랜잭션 중단, 잘못된 항목 보존, 저장 한도, 대기 중 입력, 재시도와 여러 연결의 필드 병합을 검사합니다. 파일 형식·한도·중복·잘못된 항목·트랜잭션 전체 취소·검토 후 변경·원본 삭제 범위도 검사합니다.

Chrome에서는 실제 데이터베이스 이전·재방문·여러 탭 동기화·실패 후 CSV와 재시도·320px 접근성을 검사합니다. JSON 다운로드 후 새 브라우저 환경에서의 복원, 최신 입력의 백업, 복구 원본 정리, 긴 메모의 키보드 스크롤과 늦게 읽힌 이전 파일의 결과 무시도 확인합니다. 기존 다른 기능의 브라우저 검사도 localStorage 문자열 대신 저장 완료된 IndexedDB 기록을 확인하며, 이전 형식의 입력 자료는 이전 검증을 위해 유지합니다.
