# 직군 분류 v7의 실제 자료 대조

2026-09-30에 보관된 과거 자료로 직군 분류 변경을 대조했습니다. 이번 대조에서 채용 제공자에 새 요청을 보내지 않았습니다. 실제 공고 본문·개별 검토 목록은 공개 저장소에 넣지 않습니다.

분류 규칙과 합의한 경계는 [v7 설계](design/occupation-v7.md)에 있습니다. 이 문서의 수치는 구현 담당의 실제 자료 대조 결과이며, 독립 단위·브라우저 검증의 통과를 대신하지 않습니다. 별도로 실행한 단위 검사 2,641개와 전체 DEV·PROD E2E 각각 489개가 통과했습니다. 실행 근거와 최종 합의는 [검증 기록](validation/occupation-v7-2026-09-30.json)에 기록합니다.

## 같은 입력에서 바뀐 결과

입력은 130개 게시판의 보관 공고 6,819건과, 앞서 지역 확장에서 사용한 여섯 게시판의 선별 전 원 응답 512건입니다. 보관 공고는 모두 이전 직군 버전 6입니다. 원 응답에 이전 규칙을 적용한 64건의 ID는 당시 지역 수집 스냅샷과 일치했습니다.

| 구분 | 이전 규칙 | v7 |
| --- | ---: | ---: |
| 보관 공고 중 개발·컴퓨터 연구 탐색에 포함 | 6,819 | 6,802 |
| 그중 개발·컴퓨팅 엔지니어링 | 6,700 | 6,683 |
| 그중 컴퓨터·AI 연구 | 119 | 119 |
| 선별 전 지역 원 응답에서 탐색에 포함 | 64 | 55 |

보관 공고에서 빠진 17건은 구현 전에 개별 검토한 채용 담당·전자 설계·공급업체 품질·물리적 고장 분석 직무입니다. 이 17건 외에 보관 공고의 직군이 바뀐 경우는 없었습니다.

| 제외된 주직무 | 보관 공고 수 |
| --- | ---: |
| 채용 담당 | 2 |
| 전자 설계 | 3 |
| 공급업체 품질 관리 | 6 |
| 본인의 물리적 고장 분석 업무 | 6 |

지역 원 응답에서는 위에 해당하는 10건이 빠지고, 개발 업무가 명시된 펌웨어 인턴 1건이 추가됐습니다. `Firmware Internship 2026/2027`은 개발직으로 포함하면서 세부 직무를 `unknown`으로 유지합니다.

복합 하드웨어 직함과 `- Hardware` 접미사에 따른 컴퓨팅 예외는 별도의 가상 회귀 사례로 검증했습니다. 실제 자료에서 바뀐 사례만으로 이 경계 전체의 정확도를 추정하지 않습니다. 하드웨어 팀의 기존 펌웨어·생산 검사 소프트웨어 공고와 `Applied Emerging Talent` 소프트웨어 공고는 양성 대조군으로 확인했습니다.

## 원문과 관측 시각 보존

6,819건 각각의 원본 입력이 변하지 않았고, 직군을 다시 해석한 반환값에서도 `occupation` 이외의 필드가 모두 같음을 대조했습니다. 원 응답 512건도 정규화 전후 입력이 같았습니다.

실제 버전 5 캐시를 읽는 경로에서는 130개 게시판과 정확히 기대한 6,802개 공고 ID가 남았습니다. 전체 공개·비공개·활성 확인 ID, 총 게시 수, 원래 조회·실패·재시도 시각과 과거 관측 방식 표기를 유지했습니다. 제외된 공고 수를 현재 채용 시장의 감소로 기록하지 않습니다.

업무 제목이 `WHAT YOU’LL OWN.`처럼 곡선 따옴표와 마침표를 사용하는 실제 사례가 처음에는 미확인으로 남았습니다. 제목 인식을 보완한 뒤 해당 물리적 고장 분석 공고도 기타 직군으로 분류됐으며, 공개 회귀 검사에는 별도로 작성한 가상 문장을 사용합니다.

## 해석 범위와 재현 자료

모든 변경 사례와 지정한 양성 대조군을 개별 검토했습니다. 나머지 공고를 모두 수동으로 재분류한 결과나 모집단의 오분류율은 아닙니다. 이미 선별된 캐시만으로 누락률을 구할 수 없으며, 선별 전 원 응답도 여섯 지역 출처에 한정됩니다. 현재 공고의 유효성이나 현재 회사별 채용 규모를 나타내지 않습니다.

이전 저장 기록은 당시 보관한 본문과 근거만 사용할 수 있습니다. 제목만 남은 모호한 고장 분석 공고는 미확인으로 남을 수 있으며, 잘린 본문을 새로 만들어 채우지 않습니다. 본문 밖에 별도로 보존된 업무 근거를 읽는 동작은 가상 이전 기록으로 검증합니다.

원 입력은 보호된 `.local/preserved-2026-09-28/historical-inputs.zip`에 있습니다. 압축본·관측 이력의 해시와 원래 경로 복원 방법은 [로컬 자료 보존 기록](local-data-retention.md)에 있습니다. 이번 작업에서 꺼낸 사본과 상세 대조 출력은 단계 검증·합의·Git 보존 후 정리하며, 이 문서와 최종 검증 기록에 조사 결론을 남깁니다.

독립 정리 검토에서 새 수동 판정 기록과 참고 사이트의 당시 응답·조회 기록이 기존 압축본에 없는 것을 확인했습니다. 이 자료와 복원 대응표는 `.local/preserved-2026-09-30/`에 추가로 보존한 뒤 작업용 사본을 정리합니다. 새 보관본의 생성·전체 해시 대조를 마치기 전에는 원본을 삭제하지 않습니다. 최종 소스와 보존한 조사 스크립트로 v6·v7 중간 결과를 다시 만들 수 있지만 실행 시각까지 같은 결과를 재생성한다는 뜻은 아닙니다.
