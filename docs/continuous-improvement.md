# 지속 개선 작업 기준

2026-09-30 사용자 요청을 포함한 지속 작업의 기준입니다. 다음 재개에서도 저장소 상태와 이 기준을 함께 확인합니다.

## 목표

> 별다른 이야기하지 않으면 계속 개선해줘. 전체적으로 데이터 수급, 사용성, 확장성 관점에서 관련 레퍼런스를 조사하고 개선할 점이 있는지 확인하고 개선하고 반영해줘. 반영할 점은 개선한 거 하나씩 나중에 알려주면 보고 이야기할께

한 단계의 기능 구현을 마쳤다는 이유로 이 지속 목표 전체를 완료한 것으로 바꾸지 않습니다. 현재 단계와 다음 개선 후보는 근거와 함께 구분해서 기록합니다.

추가 조건은 다음과 같습니다.

1. 작업을 끝내면 해당 작업의 임시 파일을 모두 삭제합니다. 가치 있는 소스·조사 결론·검증·합의 기록을 먼저 Git에 저장하고, 과거 원본·관측처럼 다시 얻을 수 없는 자료는 보존 위치와 이유를 기록합니다.
2. 주 구현 담당과 **Codex GPT-6 Astra Max**, **Claude Code Fable 5.1 Max**가 독립적인 설계·구현·검증 역할로 협업합니다. 문제는 세 참여자에게 공유하고, 해당 단계의 최종 결과에 전원이 명시적으로 합의해야 다음 단계로 넘어갑니다.

## 역할과 합의

| 참여자 | 담당 | 수정 범위 |
| --- | --- | --- |
| 주 구현 담당 | 레퍼런스·실제 자료 조사, 제품 구현, 통합, 문서, 단계 보존·정리 | 제품·문서·로컬 작업 자료 |
| GPT-6 Astra, reasoning `max` | 독립 설계 제안, 위험·경계 검토, 구현 코드 검토 | 기본적으로 읽기 전용 |
| Claude Code `claude-fable-5-1`, effort `max` | 독립 검증 설계, 테스트 보강·실행, 실패 재현·회귀 확인 | 테스트 파일과 로컬 검증 자료 |

각 참여자가 먼저 근거를 독립적으로 검토합니다. 이후 원래 의견과 이견을 서로 전달하고 같은 수정안에 대한 판단을 받습니다. 상대의 의견을 요약할 때 반대 이유·조건·검증 한계를 생략하지 않습니다.

설계 → 구현 검토 → 검증 완료의 각 단계에서 세 참여자의 명시적인 승인과 미해결 사항 0개를 확인합니다. 각 승인은 설계 문서의 버전·해시 또는 검토한 소스·테스트의 커밋·내용 해시를 명시합니다. 여기서 미해결 사항은 필수 수정이 필요한 결함, 반대 의견, 필수 검증의 누락을 말합니다. 세 참여자가 명시적으로 수용한 한계는 기록에 남깁니다.

한 참여자라도 반대하거나 실행할 수 없으면 전원 합의로 기록하지 않습니다. 제품 수정이 검증 이후 생기면 영향을 받는 검사를 다시 실행하고 변경된 결과를 검토합니다.

주 구현 담당이 단계의 승인·대기·이견 상태, 참여자별 판단과 미해결 항목을 기록해 공유합니다. 설계 승인과 검증 완료는 별개이며, 아직 수행하지 않은 검증에는 승인 상태를 부여하지 않습니다.

모델 선택, 실행 상태와 실제 응답 모델을 확인 가능한 범위에서 기록합니다. 별칭이 다른 버전으로 연결되거나 다른 모델로 대체되었을 때 요청한 모델이 참여했다고 보고하지 않습니다. 도구가 실제 적용된 설정을 확인해 주지 않는 부분은 요청한 설정과 구분합니다.

검증 결과는 실행 명령·범위·실패·재실행·성공·한계를 함께 기록합니다. 세 참여자의 합의를 제품의 정확도 100%나 무결점 보장으로 표현하지 않습니다.

## 단계 종료와 임시 자료 정리

관련 타입·단위 검사·빌드와 독립 E2E가 통과하고 최종 합의가 완료되면, 구현·테스트·문서를 별도 커밋으로 보존합니다. 기능 변경이 없는 문서·작업 규칙 반영에는 불필요한 E2E를 실행하지 않습니다.

그 뒤 해당 단계에서 만든 재생성 가능한 검증 빌드·캐시·보고서·스크린샷·trace·프로파일·임시 스크립트·자료 사본·worktree를 정리합니다. 소유한 검증 서버·브라우저·agent도 종료합니다. 기존 의존성·사용자 파일이나 진행 중인 다른 작업을 일괄 삭제하지 않습니다.

다시 얻을 수 없는 수집 원본과 관측 이력은 임시 검증 산출물과 보존 목적이 다릅니다. 공개 Git에는 실제 공고 본문을 넣지 않으며, 필요한 원본은 중복을 줄인 로컬 보관 자료로 남기고 위치·이유·무결성 확인을 기록합니다. 기존 보관 자료는 [로컬 자료 보존 기록](local-data-retention.md)을 기준으로 보호합니다.

정리 완료 후 남은 파일·등록 worktree·소유 프로세스와 Git 상태를 확인합니다. 사용자에게는 완료한 개선, 검증 결과와 한계, 커밋, 보존한 자료와 임시 파일 정리 결과를 보고합니다.
